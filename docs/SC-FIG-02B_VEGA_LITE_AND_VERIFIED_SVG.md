# SC-FIG-02B — Vega-Lite views and verified SVG export in Graph Studio

**State:** release candidate 0.163.1.6, default off. Not deployed. Preview only.

FIG-02B extends the SC-FIG-01 `sc.figure-bundle.v1` renderer. It is not a second Graph Studio and
keeps no figure store: a bundle and its view files are opened from local files, verified, drawn and,
on request, exported to local downloads.

## Switches

| Option | Default | Effect |
|---|---|---|
| `sc_lab_figure_bundle_renderer_enabled` | `0` | SC-FIG-01 renderer (Plotly, PNG). |
| `sc_lab_fig02b_vega_lite_enabled` | `0` | Vega-Lite views and SVG export; ignored unless the renderer is on. |

The filter `sc_lab_fig02b_vega_lite_enabled` accepts only boolean `true`.

All are BSD-3-Clause and are packaged by `scripts/package_vega_vendor.py` from the npm tarballs,
which must match the pinned registry integrity. The interpreter's ES module is mechanically rewritten
into a classic script; each library's `SOURCE.json` records the details. A rerun is byte-identical.
WordPress serves none of them unless all three match (fail closed).

## View contract (`usermeta.sc`, profile `sc-vega-lite-v1`)

- **Grammar:** only inline `data.values` (at most 20,000 flat rows) is accepted. Marks and transforms
  come from an allow-list: `filter` with an object predicate only, `fold`, `bin`, `aggregate`,
  `timeUnit` and `stack`. Expressions, `params` and selections, `calculate`, `lookup`, links, images,
  projections, and every `url` or `datasets` entry are refused.
- **Dataset identity:** `datasetSha256` must equal the canonical-JSON hash of `data.values`. It must
  also be one of the bundle's `sourceRefs[].sha256` or `calculationRefs[].outputSha256`.
- **Units:** every encoded field needs a `label` and a `unit` (`"1"` for dimensionless, `"category"`
  for labels). An explicit axis or legend title must contain the unit.
- **Uncertainty:** `kind` is one of `none`, `sd`, `se`, `ci90`, `ci95`, `pi95` or `range`, and comes
  with a statement. Declared bound fields must be numeric and drawn by an error bar, band, rule, area
  or rect layer.
- **Evidence:** `evidenceField` gives every row an evidence class. A row may never be `observed`
  unless the bundle is `observed`. When classes are mixed, the class must be visually encoded
  (colour, shape, dash or facet).

## Rendering and export

Vega-Lite compiles to Vega, which is parsed with `ast: true` and run by the expression interpreter.
The renderer is SVG, and a loader refuses every request. The page needs no `unsafe-eval`; the
Chromium harness proves this with a CSP that blocks `eval`.

Export (Vega-Lite and Plotly views):

1. Serialise to SVG and check every element against an allow-list. Anything else is refused: no
   script, `foreignObject`, image, link, event handler, external `url()` or `@import`.
2. Embed `<title>`, `<desc>` and `<metadata id="sc-figure-provenance">` (`sc.figure-svg-provenance.v1`).
   The metadata records the figure, evidence class, dataset hash, fields and units, uncertainty,
   source and calculation references, reproducibility and the view's hash.
3. Re-parse and re-verify the bytes, then emit `sc.figure-export-receipt.v1`. The receipt holds the
   SHA-256, size, bundle hash and an `artifactEntry` the producer can add to the next bundle revision.
4. A bundle revision that lists the exported SVG renders it as a verified static view. An SVG whose
   provenance names another figure or view is refused.

Exports repeat byte-for-byte in the same browser and fonts. Across machines, text measurement can
differ, so cross-machine identity is not claimed.

## Tests

`scripts/test_vega_lite_fig02b.sh` runs:

- the Node contract (grammar, `usermeta.sc`, table model, and Python/JavaScript dataset-hash agreement);
- the PHP loader, including a modified vendor file;
- `tests/chromium-fig02b-vega-lite.html`, which draws the synthetic ERW, Metrics and combined
  Plotly + Vega-Lite figures, then checks the tables, exports, receipts, round trip, refusals and
  that no network request was made.

Fixtures in `tests/fixtures/fig02b-vega-lite` are synthetic. They are generated by
`build_fixtures.py` and are not Wexford or Metrics data.
